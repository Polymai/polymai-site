Readiness shows connected, missing, and unused services. Secrets never belong in public files; the storage and data boundaries are documented below.

Credentials and saved data

Secrets, public configuration, and project data are kept separate.

Select a card for the exact boundary. Polymai uses VS Code’s encrypted secret storage for credentials, separates public runtime values, and does not make an absolute security promise.

Secret credentials

Encrypted locally; sent directly to the provider.

API keys, private tokens, database passwords, and webhook secrets are kept in VS Code SecretStorage, not normal settings, generated frontend files, or the extension package. When used, they go over HTTPS directly to the selected AI, GitHub, Supabase, Stripe, or email provider. For generated Supabase apps, runtime secrets are placed in your own server-side Edge Function environment.

Public app configuration

Visible by design; never a substitute for access control.

A Supabase URL and publishable/anon key, Stripe publishable key, Price IDs, or Google OAuth client ID can appear in generated frontend configuration. These values are designed to be public. Protect the data behind them with RLS, authorization, and server-side secrets as described in Supabase’s API-key guidance.

Project content

Local workspace history is useful, but not a secret vault.

Project files, prompts, logs, indexed content, and local history stay in the workspace and normal VS Code local storage. A prompt is sent to the selected AI or coding agent only when you run that action, and source can be published when you choose to publish it. Never put credentials or sensitive customer data in prompts, files, logs, or project notes.

Polymai account data

Account records support access, quota, and app status.

Your activation token is encrypted locally. The Polymai account backend stores a SHA-256 hash plus limited token metadata—not the raw token—and uses it over HTTPS for activation, quota, and app-stat checks. Account records contain identity, plan, usage, generated-app status, and relevant billing references; extension app records use hashes rather than raw workspace paths or prompts.

Use a protected device, test and least-privilege keys where possible, and rotate or revoke a provider key if you suspect exposure. Review generated code and repository contents before publishing.
